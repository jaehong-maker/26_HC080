# 앰비언트 연속 분사 정책

확인일: 2026-11-02

## 동작

1. 최초 진입 시 이전 출력 정지 명령을 POLL로 전달한다. 그 POLL의 소음값은 제외한다.
2. 이후 새 유효 측정값을 최소 3초간 모아 평균으로 향·음악·LED를 선택한다. 과거 평균이나 기본값을 대신 사용하지 않는다.
3. 서버가 선택한 향의 `duration=60` 명령을 기기의 POLL로 전달한다.
4. 소음은 최근 60초 이동평균으로 분석한다. 구간이 바뀌면 새 향과 음악을 선택하며, 변경한 향에도 60초 분사 허용 시간을 적용한다.
5. 같은 구간·같은 향에서도 분사를 유지하며, 60초마다 해당 소음 구간의 다른 곡으로 음악만 바꾼다. 최초 60초만 분사한 뒤 끝내거나, 3초만 분사하는 정책을 대체한다.
6. 구간은 Quiet <60, Moderate 60~79, Loud >=80이다.

최초 및 소음 구간 변경에 따른 향 선택 시 최신 POLL의 슬롯별 잔량도 확인한다. 잔량 15% 미만·누락·비정상 값인 카트리지는 제외하고 해당 소음 구간의 다음 우선순위 향을 선택한다. 같은 향이 여러 슬롯에 있으면 사용 가능한 실제 슬롯을 선택한다. 후보가 없으면 음악만 먼저 바꾸지 않는다. 기기의 실제 센서 유효성과 릴레이 동작 여부는 펌웨어의 안전 검사 및 진단 로그로 별도 확인한다.

현재 POLL 간격은 약 2초다. 따라서 초기 유효 샘플이 걸치는 시간은 보통 약 4초이며 추천·통신 시간도 추가된다. 정확히 3초간 연속 PCM을 평균내는 펌웨어 변경은 포함하지 않는다.

## 마이크 유효성 POLL 규약

- `microphone_valid=true`와 유한한 0 이상 `db_level`이 함께 있어야 유효 샘플이다. 정상 측정된 `db_level=0`도 초기 측정과 이동평균에 포함한다.
- `microphone_valid=false`·유효성 필드 누락·`db_level` 누락·비정상 수치는 샘플에서 제외한다. 0이나 기본 소음값으로 대체하지 않으며 추천 판단을 실행하지 않는다.
- `db_last_sample_time`은 유효 샘플에만 갱신한다. 무효 POLL이나 분석 구간 초기화는 마지막 유효 측정 시각을 바꾸지 않는다.
- 마지막 유효 측정 이후 10초 이상 지나면 이전 평균 샘플을 비우고 분석을 재시작한다. 초기 측정 중이면 초기 샘플도 비우고 새 유효 샘플이 최소 3초를 채우기를 기다린다. 10초 미만의 무효 구간에는 이전 유효 샘플만 유지한다.
- 무효 POLL은 연속 소음 유지 시간을 즉시 끊는다. 이후 유효한 높은 소음이 다시 들어온 시점부터 유지 시간을 새로 센다.
- 무효 POLL에서도 잔량 갱신·기존 향의 예정된 분사 허용 갱신·대기 명령 전달·사용자 정지는 계속 처리한다. 새로운 향·음악 추천에는 무효 측정을 사용하지 않는다.
- 응답에도 `microphone_valid`를 제공하며 무효 상태의 `db_level`은 생략한다. 긴 단절 뒤 평균이 없으면 `db_avg`·`db_stddev`도 생략한다. 앱 조회만으로 측정 시각이나 샘플을 갱신하지 않는다.
- 규약 적용 전 저장된 샘플은 합성된 0이 섞였을 수 있어 최초 POLL에서 한 번 비운다. 기존 향·음악 및 명령 전달은 유지한다.

## 같은 소음 구간의 음악 교체

- 향·음악 최초 선택 및 구간 변경 시 음악 교체 기준 시각을 저장한다. 마지막 선택 후 60초가 지나고 유효한 60초 분석 구간이 확보된 기기 POLL에서 음악만 교체한다. POLL 간격과 초기 분석 시작 시각에 따라 첫 교체는 약 62초 후에 전달될 수 있다.
- `AMBIENT_MUSIC_BY_BUCKET`의 Quiet·Moderate·Loud별 곡 목록에서 현재 곡의 다음 곡을 선택하고, 목록 끝이면 처음으로 돌아간다. 현재 곡은 재선택하지 않는다.
- 음악 교체는 현재 향·LED·분사 명령·잔량·분사 허용 시간에 손대지 않는다. 분사 허용 시간 갱신은 기존의 별도 일정대로 동작한다. 음악 교체에는 AI를 호출하지 않는다.
- 별도 분사 명령이 없으면 `spray=-1`, `app_command=false`, `music=새 트랙 번호`로 보낸다. 기기는 앰비언트 POLL의 새 음악을 분사 명령 유무와 별개로 적용한다.
- 기기가 보고한 곡이 서버가 선택한 곡과 다르면 먼저 기존 곡 명령을 재전달한다. 정상 반영 후에는 `music=0`으로 유지하고 다음 교체 시점을 기다린다.
- 무효 소음값·초기 측정 중·10초 단절 이후 새 분석 구간이 완성되기 전에는 교체하지 않는다. 소음 구간 변경 시에는 기존 향·음악 재선택을 우선한다.
- 앱 POLL은 음악 교체를 실행하지 않는다. 정지·모드 변경·세션 변경과 경합하면 조건부 쓰기로 오래된 음악 변경을 폐기한다.

## 분사 허용 시간 갱신

- 분석 구간과 분사 허용 시간은 별도 설정이다. 현재는 각각 60초다.
- 기기 POLL로 명령을 전달한 시점을 기준으로 만료 시각을 기록한다. 앱의 조회로는 허용 시간이 시작되거나 연장되지 않는다.
- 현재 설정은 만료 30초 전 다음 60초 명령을 한 번 발행한다. 매 POLL마다 재발행하지 않는다.
- 갱신 시 향은 현재 향을 유지하며 AI를 호출하지 않는다. 같은 음악은 `music=0`으로 유지한다.
- 새 명령이 없는 기기 POLL은 `spray=-1`, `app_command=false`다.
- 통신이 끊기면 마지막으로 전달된 명령의 허용 시간까지만 분사한다. 서버에 연결되지 않은 기기를 앱 조회만으로 갱신하지 않는다.
- 전달 지연·응답 유실이 갱신 여유 시간을 초과하면 분사가 끊길 수 있다. 이 경우 기기가 자체 연장하지 않는 기존 동작을 유지한다.

## 정지와 펌웨어 규약

- 사용자 정지는 갱신 예약·토큰·대기 명령을 해제한다. 저장과 전달 시 조건을 확인하여 이전 세션의 명령이 정지를 덮어쓰지 않게 한다.
- 싫어요로 고른 대체 향도 같은 60초 허용·갱신 정책을 따른다.
- 출력은 후속 POLL로 적용하며 직접 추천 응답은 진단용으로만 취급한다.
- 펌웨어의 명령당 1~270초 범위, 잔량·센서 차단, 정지 세대 번호 보호를 유지한다.
- `ambient + spray=0`은 펌프 정지, `ready/off`는 모드·펌프·음악 정지다.

## 적용 상태와 확인 방법

서버 소스와 오프라인 검증 코드를 로컬에 반영했다. 별도로 DFPlayer ACK 누락 시 음악 명령 대기가 메인 루프를 멈추고 1.5초 센서 유효 시간 초과로 펌프가 차단되는 경로를 재현했다. 이에 펌웨어의 DFPlayer 초기화를 ACK 대기 없이 동작하도록 최소 수정했다. 센서·잔량 안전 차단과 GPIO 제어는 유지한다. GitHub 커밋·업로드, AWS 배포, 펌웨어 업로드, 실물 검증은 하지 않았다.

검증 명령: `python -B -m unittest discover -s cloud_config/tests -v`

음악·센서 경합 검증: `python -B -m unittest discover -s Hardware/tests -v` (설치된 DFPlayer 라이브러리와 실제 펌웨어 함수로 컴파일하며, ACK 없는 조건에서 변경 전 차단·변경 후 최대 180ms 처리를 확인한다. MSVC와 DFPlayer 라이브러리가 필요하다.)

실물에서는 최초 측정 후 선택 향의 60초 분사를 확인하고, 같은 향으로 첫 60초 경계를 넘을 때 분사가 유지되면서 음악만 다른 곡으로 바뀌는지 먼저 확인한다. 이후 향 변경·사용자 정지·통신 단절을 따로 확인한다.
