# 앰비언트 반복 분사 운전 정책

확인일: 2026-11-02

## 확정된 동작

1. 최초 3초간 측정한 값으로 서버가 첫 향과 음악을 결정한다.
   이 3초는 초기 측정 시간이며 분사를 3초로 제한한다는 뜻이 아니다.
2. 선택한 향을 3초 분사하고, 강도에 따라 강 3초·중 6초·약 9초 휴지 후
   다시 분사하는 동안 이후 60초 구간의 소음을 분석한다.
3. 소음 모드가 켜진 동안 다음 측정 구간에서도 분사를 유지한다.
   서버가 소음 판단에 따라 향을 변경한다. 같은 향이라고 분사를 종료하지 않는다.
4. 음악·LED·분사 명령은 후속 POLL로 전달한다.
   직접 추천 응답은 진단 기록만 남긴다.
5. 기존의 '구간 변경 시 3초 1회 분사, 같은 구간에서는 분사하지 않음' 정책을 대체한다.
6. 소음 구간은 Quiet <60, Moderate 60~79, Loud >=80이다.
7. 서버의 duration은 분사와 휴지를 포함한 전체 운전 시간이다.
   휴지 중 음악·LED는 유지하고, 전체 시간 만료 시 펌프만 정지한다.

## 현재 코드와의 차이

GitHub main에서 AMBIENT_ANALYSIS_WINDOW_SECONDS=60,
AMBIENT_DURATION_SECONDS=3을 확인했다.
해당 main 검토 시 서버는 추천 시 3초 명령을 생성하며, 같은 구간에서는 새 분사 명령을
발행하지 않는 경로가 있다. 분석 시간만 60초로 바꾸면 연속 분사가 되지 않는다.

현재 펌웨어는 POLL의 duration이 지나면 펌프만 정지한다.
spray=-1은 기존 종료 시간을 연장하지 않는다.
따라서 duration=60을 한 번 보내는 것만으로는 첫 1분 이후 연속 동작을 지원하지 않는다.

## 서버 구현 요구사항

- 최초 3초 측정 및 초기 선택 처리를 확인하고, 그 이후 분사를 시작한다.
- 분석 구간 60초와 펌프에 허용하는 분사 시간을 별도로 관리한다.
- 같은 향을 유지할 때에도 소음 모드의 지속 동작을 서버가 명시적으로 허용해야 한다.
  유효 시간 갱신 명령이 필요하며, 다음 명령의 전달 시간을 고려해 기존 종료 전에 전달한다.
- 갱신은 일반 POLL마다 명령을 반복하는 방식이 아니라 서버가 관리하는 별도 갱신 시점에 수행한다.
- 새 명령이 없는 POLL은 spray=-1, app_command=false를 유지한다.
- 향 변경 명령은 active_mode=ambient, app_command=true,
  서버가 선택한 spray와 유효한 duration을 함께 전달한다.
- music>0은 현재와 다른 곡일 때 적용하며, music=0은 기존 음악을 유지한다.
- 사용자 정지는 대기 중인 분사 갱신보다 우선해야 한다.
  정지 후 오래된 갱신 명령이 다시 발행되지 않도록 서버 상태와 대기 명령을 함께 정리한다.

## 유지할 펌웨어 동작

- 명령당 duration 허용 범위 1~270초. 분사·휴지를 포함해 계산한다.
- 센서 무효·잔량 부족 차단.
- 정지 세대 번호 보호.
- 앰비언트의 spray=0은 펌프만 정지, ready/off는 모드·펌프·음악 정지.
- 서버 명령이 끊기면 마지막으로 허용받은 duration까지만 분사한다.
  전체 시간 만료 후 새 서버 명령 없이 운전을 연장하거나 다시 시작하지 않는다.
- 공유 SCK 읽기, GPIO·릴레이 제어 방식, LED 중복 전송 제거 유지.

## 적용 상태

이 문서는 서버 담당자 전달용 요구사항이다.
최신 서버 소스는 GitHub main에서 읽기만 했으며 로컬 구버전에 덮어쓰거나
커밋·푸시·머지·배포하지 않았다.
로컬 펌웨어에는 3초 분사와 강도별 휴지 반복, 전체 시간 종료 처리를 추가했고
진단 v11로 표시한다. ESP32 min_spiffs 빌드와 시간 모의 검증을 통과했으며
기기 업로드와 실물 검증은 아직 남아 있다. 서버의 후속 운전 갱신 구현은 별도이다.

서버 적용 후에는 첫 60초 경계를 지날 때에도 같은 향의 분사가 유지되는지
한 가지 실물 테스트부터 진행한다. 이후 향 변경과 사용자 정지를 별도로 확인한다.
